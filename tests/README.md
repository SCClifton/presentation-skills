# Behavioural evaluation

Use `cases.json` as a small observable acceptance set. All facts are fictional. Do not supplement the scenarios with real client or employer information.

For positive cases, start an independent host session with this skill discoverable and give the request without the expected answer or this rubric. Save the output outside the repository. Inspect whether the host actually loads the skill, follows linked references when needed, and produces the requested argument and deliverable.

For negative cases, inspect whether the host completes the narrow task without loading this presentation skill. A self-reported match is weaker evidence than a recorded skill or file-read event. Explicit invocation tests loading and use, but does not establish automatic selection.

Evaluate positive outputs on:

- Fidelity to the brief and requested deliverable.
- Coherent narrative and appropriate opening and ending.
- Numerical accuracy and separation of measured results from proposals.
- Useful variation in arrangements, chosen for the information.
- Readability, sources, evidence limits, and editable objects where requested.
- Ability to change the brand layer without changing the facts or requiring edits to the skill.

Do not require exact wording, a fixed chapter list, or the same layouts across models. Record model and host versions, discovery configuration, prompts, observable skill loads, output paths, failures, and limitations. Test each intended host independently; shared packaging does not prove shared behaviour.

If a host is unavailable or unauthenticated, record it as untested. Do not substitute a hand-written answer and report a cross-model pass.
